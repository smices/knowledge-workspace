# 数据库迁移

项目使用 Alembic 管理 PostgreSQL 结构。执行迁移前应备份数据库，并确认 `DATABASE_URL` 指向目标环境。

```bash
.venv/bin/alembic upgrade head
```

Docker 和 Kubernetes 部署会在 API 启动前执行同一迁移。回滚必须先审查对应 revision 的 `downgrade()`，不得在生产环境直接尝试未验证的降级。

## 本地用户与会话版本升级

账号功能新增本地用户凭据表与 `principals.session_version`，保留初始化管理员的既有凭据，不从环境变量重置密码。先执行迁移，再切换同版本 API。

同批迁移扩容审计资源标识至 256 字符，并补齐首页常用问题依赖的 `query_events` 表及索引。新角色使用 UUID 标识，保留历史角色 ID，按租户与角色名查找。

历史初始化管理员用户名保留兼容读取；其旧密码登录/改密验证兼容至 4096 字符，新安装及所有新设密码仍为 16–128 字符。此上限不承诺兼容旧版任意无限长度密码，超过上限的安装需另行授权处理凭据。

升级会拒绝不含会话版本的旧 Cookie，用户需要重新登录。启用 OIDC 前，应由管理员预准入正确的稳定 subject；未知 subject 不再自动建号。历史账号的身份类型必须来自可信登记，不能把任意旧记录自动转换为 IdP 账号。

已有 `.env`、Secret 和运行服务不会被源码更新自动改写。检查正式部署使用 local/oidc 登录模式、真实会话密钥、公开入口与 Cookie 安全配置后，再执行已授权的发布流程。
